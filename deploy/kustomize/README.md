# Kustomize overlays

This directory is a GitOps-friendly projection of the
[`deploy/helm/boxxkite`](../helm/boxxkite/) chart. Helm remains the source of
truth: [`base/helm-rendered.yaml`](base/helm-rendered.yaml) is generated by
[`generate.sh`](generate.sh), and `generate.sh check` fails when the committed
base no longer matches a fresh Helm render.

The overlays are ordinary Kustomize directories that can be used by Argo CD,
Flux, or `kubectl`:

```bash
kubectl apply -k deploy/kustomize/overlays/dev
kubectl apply -k deploy/kustomize/overlays/staging
kubectl apply -k deploy/kustomize/overlays/prod
```

Review the rendered output first, especially the storage and Secret settings:

```bash
kubectl kustomize deploy/kustomize/overlays/prod
```

The staging and prod patches add an example storage `ipBlock` using
documentation-only TEST-NET ranges. Replace those CIDRs with the actual
private endpoint range for the storage service before applying either
overlay. Do not replace them with `0.0.0.0/0`; the chart deliberately fails
closed when storage egress is not configured.

The overlays change only resources the chart actually renders:

| Overlay | Namespace | Chart-backed customization |
|---|---|---|
| `dev` | `boxxkite-dev` | One warm-pool target and a shorter pod timeout |
| `staging` | `boxxkite-staging` | Medium warm-pool target and storage egress example |
| `prod` | `boxxkite-prod` | Larger warm-pool target and storage egress example |

The chart does not render a Deployment, Service, Ingress, or session Pod.
`SandboxManager` creates session Pods at runtime, and the control-plane is a
separate deployment. Consequently these overlays do not invent pod resource
limit or ingress-class patches. Change runtime resource defaults through the
Helm values and `src/boxxkite/resource_config.py` parity workflow, and deploy
the control-plane separately as described in the repository documentation.

The ValidatingAdmissionPolicy and its binding are cluster-scoped resources.
Each overlay gives them an environment-specific name and keeps the namespace
transformer away from those two resources so dev, staging, and prod can
coexist in one cluster. The namespace-scoped RoleBinding subject is patched
to the matching control-plane ServiceAccount namespace as well.

## Regenerate or verify the base

Run this after changing the Helm chart:

```bash
deploy/kustomize/generate.sh write
deploy/kustomize/generate.sh check
```

Do not hand-edit `base/helm-rendered.yaml`. The focused tests build the base
and all three overlays, verify the generated artifact, check namespace and
admission-policy references, and reject broad storage egress.
